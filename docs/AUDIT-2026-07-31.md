# AUDIT 2026-07-31 — read-only, produced from outside this repo

**What this is.** A full read-only audit of the 1066 Test Mod, run from the
Mongol Resurgence repo by three parallel Opus 5 agents — one on setup data, one
on runtime script, one on the documentation. Nothing in this repo was written
or edited by that session except this file.

**Why it exists now.** The Mongol Resurgence session of 2026-07-31 measured
several engine laws in a running game that bear directly on this mod, and two
of them contradict what this mod's own documents say. Those are in Part 4.

**THIS DOCUMENT IS WRITTEN TO BE CHECKED, NOT BELIEVED.** Every finding carries
a `VERIFY:` line — an exact command or file:line to look at — so a different
model, or the author, can confirm or refute it independently. If a `VERIFY`
step does not reproduce, the finding is wrong; say so and strike it. Several
first-pass findings were struck exactly that way during the audit and are
recorded in Part 6 so they are not re-derived.

**Standing rule applied throughout:** validate strictly what this mod wrote;
merely *report* what vanilla shipped. A check that fails on Paradox's own data
blocks our work over someone else's bug.

## PART 0 — How to verify anything here

**Trees.**

```
VANILLA (read-only)   /e/SteamLibrary/steamapps/common/Europa Universalis V/game
                      (in Python:  E:/SteamLibrary/steamapps/common/Europa Universalis V/game)
THIS MOD              <parent>/1066 Test Mod
ENGINE SCRIPT DOCS    <this mod>/docs/EU5-Vanilla-Script-Docs/
                      effects.log · triggers.log · modifiers.log ·
                      event_targets.log · on_actions.log · data_types/
```

The script docs are the authority for **what exists and at which scope**.
Vanilla only ever shows what someone happened to use. Look at the logs first.

**Three method laws that this audit obeyed, and any re-check must too.**

1. **Token/brace parsing over comment-masked text — never line-anchored regex.**
   1337 of vanilla's 4150 province blocks in `definitions.txt` are multi-line;
   a line-based parser silently drops 38 % of the map. `^TAG` also misses a
   file's FIRST tag, because the BOM sits on that line.
2. **Prove every scan on a known positive before trusting a clean result.** A
   suspiciously clean negative is this project's recurring failure mode. Two
   findings in this audit were withdrawn at exactly that step (Part 6).
3. **Diff against the same scan run on vanilla**, and report only the delta.

**Leaf detection, one specific trap.** Keying leaf blocks in `definitions.txt`
on the `_province` suffix **drops 1289 locations** — 159 of vanilla's 4309 leaf
blocks are named otherwise (`south_farthing` at `definitions.txt:165` holds
ICE's capital `thingvellir`; also `*_nadu`, `*_coast`, `*_garjats`). Structure
gives 28 573 locations, suffix-matching gives 27 284.

## PART 1 — DEFINITE BUGS

### D1. Six landed countries declare a capital they neither own nor claim

A `LOCATION_GRANTS` transfer moved the capital to another tag and `capital =`
was never updated.

| Tag | `10_countries.txt` | capital | now owned by | keeps |
|---|---|---|---|---|
| ETA | 14218 | `etampes` | FRA | 1 (`gien`) |
| AAL | 31015 | `qutayfah` | FAT | 5 |
| FDL | 31068 | `tadmur` | HLB | 6 |
| FRI | 36605 | `groningen` | UTR | 8 |
| JLM | 30012 | `van` | BYZ | 4 |
| ORM | 53521 | `hormuz` | SEL | 22 |

The capital appears in none of their lists — not owned, not claimed.
`tools/build_setup.py:1719-1724` documents the ETA transfer in prose
(*"etampes from ETA … ETA keeps gien"*), so the move was intentional and only
the `capital =` line was forgotten. `CAPITAL_FIXES` (`build_setup.py:1748`)
exists for exactly this and covers none of the six.

Vanilla ships 10 of the same class, so the engine tolerates it and all six
still *discover* their capital — which is why nothing logs. It is still wrong:
a capital outside the realm is a real mechanical state, not a cosmetic one.

> **VERIFY:** for each tag, open its block and confirm the `capital =` value
> appears in no `own_control_core` / `our_cores_conquered_by_others` list in
> that block; then grep the same location name across `10_countries.txt` to see
> which tag now holds it. Do this with a brace walker, not `grep -A`.

**Fix shape:** add the six to `CAPITAL_FIXES`, or re-point each capital at a
location the tag still holds.

### D2. `ABS` and `FAT` have no `parliament_type`

`10_countries.txt:58274-58297` (ABS) and `:58613-58639` (FAT). Both include
only `expl_middle_east` / `expl_muslim_mediterranean` — **discovery-only
templates**, carrying `discovered_regions`/`_areas` and nothing else — then
hand-write `government = { type = theocracy … }` inline with all 13 sliders and
both laws, but no `parliament = { parliament_type = … }` block.

These are **the only two landed country blocks in the built game**, mod or
vanilla, without one. The engine answers with
`initialize_from_bookmark.cpp:1719`.

Root cause is a rule in this repo that is one item short. `EU5-ERROR-DECODER.md`
:677-687 says *"restate BOTH laws and the sliders"*. A government template
supplies **four** things, and `parliament_type` is the fourth — nested inside a
`parliament = { }` block, which is why it was missed. 159 of vanilla's 205
templates carry it; all 13 direct uses in `10_countries.txt` are the nested
form.

> **VERIFY:** `grep -c parliament tools/build_setup.py` → expect **0**. Then
> open the two blocks and look for `parliament`. Then check any other block
> that includes a government template and confirm it inherits one.

**Fix shape:** add `parliament = { parliament_type = council }` inside each
block's `government = { }` — the value vanilla's comparable Muslim monarchies
use (`templates/muslim_monarchy_no_abrahamic_dhimmi.txt`). And extend the
decoder rule to all four.

### D3. `map_NRM` silently redefines a live vanilla colour, and repaints the Norman culture with it

`main_menu/common/named_colors/zz_1066_map_colors.txt:4` defines
`map_NRM = hsv360 { 45 85 90 }`. But `map_NRM` **already exists** at vanilla
`main_menu/common/named_colors/02_map.txt:217` (`rgb { 131 138 116 }`), and it
is consumed by two vanilla records this mod does not override:

- `in_game/setup/countries/france.txt:169` — Normandy's country colour
- `in_game/common/cultures/french.txt:492` — **the Norman culture's colour**

`zz_` loads last, so both silently become the mod's gold. Normandy's `color2`
stays vanilla's grey-green, so primary and secondary no longer match. The
file's own header comment says these keys were verified absent from vanilla —
the check was run on **RGB triples, not on key names**.

Same class, harmless in effect but the header claim is equally false:
`map_SEV:12` collides with `02_map.txt:88`, `map_TOL:16` with `02_map.txt:155`.
Neither is referenced by vanilla, so only the claim is wrong.

> **VERIFY:** `grep -n "map_NRM\|map_SEV\|map_TOL" "<vanilla>/main_menu/common/named_colors/02_map.txt"`
> → expect hits at 217, 88, 155. Then
> `grep -rn "map_NRM" "<vanilla>/in_game/"` → expect `france.txt:169` and
> `cultures/french.txt:492`.

**Fix shape:** either rename the mod's key (e.g. `map_NRM_1066`) and point the
consumers at it, or accept the vanilla colour. Do not leave a redefinition that
also moves a culture.

### D5. A visible, dead hint button on the situation panel

`norman_conquest.gui:64-65` blanks **both** `visible_hint` and `onaction_hint`.
In the template (`in_game/gui/shared/cards.gui:2537-2539`) the default of
`visible_hint` is `visible = no` — so blanking it **makes the button appear**,
and blanking `onaction_hint` removes its tooltip and its action.

Measured: **19 of 19** vanilla situation panels that blank `visible_hint`
supply a real `onaction_hint` (`hundred_years_war.gui:78-83`,
`rise_of_the_ottomans.gui:66-73`); **zero** blank both.

> **VERIFY:** read `cards.gui:2537-2539` for the default, then grep the 19
> vanilla situation `.gui` files for `blockoverride "visible_hint"` and check
> each one also has `onaction_hint`.

**Fix shape:** simply do not override `visible_hint`. The situation correctly
has no `hint_tag` (none is defined in `common/scriptable_hints/`), so there is
nothing for the button to do.

## PART 2 — SUSPECT (real, but the consequence or the reading needs confirming)

### S1. The wargoals' `defender` blocks are unrestricted — England can annex Normandy or Norway outright

`in_game/common/wargoals/zz_1066_norman_conquest.txt:21-24` and `:43-46` set
`conquer_cost`/`subjugate_cost` but omit `allowed_locations`. The vanilla model
the file cites mirrors the restriction on **both** sides:
`00_default.txt:585-604` attacker **and `:605-624` defender**.

So a victorious England can take Normandy or Norway itself, while
`casus_belli_limits_conquest_to_britain_tt` promises the war is fought for
Great Britain.

> **VERIFY:** read `00_default.txt:585-624` and compare the two halves against
> the mod's two wargoals.

### S2. Unguarded `is_at_war_with = c:ENG`

`in_game/common/situations/norman_conquest.txt:89, :90, :108, :132` and
`in_game/events/situations/norman_conquest.txt:64, :172, :203, :247`, none
preceded by `country_exists = c:ENG` in the same AND.

`c:TAG` on the right of a comparison errors every tick while the tag is
off-map. ENG exists at 1066.9.15 and the situation closes in early 1067, so
this only bites if England is fully annexed mid-situation — which the
`superiority` wargoal permits. **`can_end` (`:89`) is the one that matters**:
it is evaluated every tick until the situation closes.

### S3. Three months of the NRM retry window are unreachable

`on_monthly`'s Normandy branch runs to `1067.3.31`
(`situations/norman_conquest.txt:131`) but `can_end` fires from `1067.1.1`
(`:88`) as soon as neither war is running. If no war exists, the situation
closes on 1 January and the January–March retries never happen.

### S4. `leave_all_wars_with = c:ENG` runs unconditionally inside the monthly limit

`situations/norman_conquest.txt:111, :136`. It sits outside the inner `if`
guards, so in any month the outer limit passes it will also pull Norway or
Normandy out of an *unrelated* war they happen to share with England.

### S5. `norman_conquest.1` reaches five hard-coded tags while `visible` admits all of western Europe

`situations/norman_conquest.txt:56, :60, :69, :80, :83`. Vanilla HYW broadcasts
its intro to `every_country` with a western-Europe capital
(`hundred_years_war.txt:40-49`). A player France or Flanders sees the panel with
no introduction. DAN and SCO receive `.1` and then have no further role.

### S6. `has_casus_belli_on` is an ANY-CB test gating a SPECIFIC-CB grant

`situations:113, :138`; `events:67, :176, :208, :250`. The trigger takes no
`type`. If the country already holds *any* CB on England, the `add_casus_belli`
is skipped and the next block calls `declare_war_with_cb = { type =
casus_belli:cb_norwegian_invasion }` for a CB it may not hold. Harmless today
because `on_start` grants the right CB first — but the guard is doing nothing
useful and would hide a real failure.

### S7. `map_NOR` is invented; Norway's real colour is `map_norwegian`

`zz_1066_map_colors.txt:5`. Norway's political colour is `map_norwegian`
(`_scandinavia.txt:51`, `cultures/scandinavian.txt:61`). So in the situation map
mode the English side matches England's political colour (`map_ENG`, correctly
not redefined) while the Norwegian side does not match Norway's — the opposite
of HYW, which uses both real colours.

### S8. `kill_character` with a database `location:` link is unattested

`events/situations/norman_conquest.txt:113-116, :295-298`. `location:<key>`
resolves fine in general (1369 distinct vanilla uses), but **zero** vanilla
`kill_character` blocks pass a database link — all five pass a scope
(`flavor_teu.txt:1394`).

### S9. `can_see_situation` inside `on_ended`

`situations/norman_conquest.txt:183`. The trigger exists at the right scope,
but vanilla only ever calls it while a situation is *active*; HYW's own
`on_ended` filters with `capital.sub_continent` instead
(`hundred_years_war.txt:191-196`). Whether it still returns true after the
status change is **UNPROVEN**.

### S10. `DUB` and `ULD` write `starting_technology_level = 3` over their template's `2`

`gaelic_tribe.txt:1` declares `2`; all 29 vanilla users of that template write
none. Which value survives is **UNPROVEN** — the ABS probe
(`KNOWLEDGE.md:1449-1452`) established later-key-wins across the include/block
merge, and both includes sit *after* the tech line in these blocks, which would
mean the explicit `3` is dead. Root cause is mechanical: `build_setup.py`
hardcodes `starting_technology_level = 3` at 16 sites with no comparison
against the include's own value.

### S11. Two dead defines files carrying a self-refuting comment

`in_game/common/defines/00_1066_dates.txt` and
`main_menu/common/defines/00_1066_dates.txt` sit in directories **vanilla does
not have**. The only `common/defines` in the game is
`loading_screen/common/defines/`, and `START_DATE` is defined exactly once, at
`loading_screen/common/defines/00_defines.txt:2`. Both dead copies carry the
comment *"zz_ prefix here because vanilla's own 00_defines.txt lives in this
same folder"* — false for them, and self-refuting, since they are named `00_…`,
which sorts *before* `00_defines.txt`. The load-bearing copy,
`loading_screen/common/defines/zz_1066_dates.txt`, is correctly named.

Net effect on the game today: nothing. Net effect on the harness: the check
`start/end date mirrored and consistent: 3 items` gives false confidence that
three live files agree, when only one is live.

### S12. Four historically-accurate minors rule with no regent

FRA `fra_philippe_i_capet` (14), HOL `hol_dirk_v` (14), HUN
`hun_salamon_arpad` (13), OGK `ogk_heinrich_iv_salier` (15), against
`ADULT_AGE = 16`. The mod sets `active_regent` **0** times; vanilla sets it 28
times. Vanilla's idiom is *no `ruler` + `active_regent`*, so there is no direct
precedent for underage-ruler-plus-regent — which is why this is suspect rather
than a bug.

## PART 3 — NEEDS A DECISION

### N1. Twelve localisation keys silently override vanilla, globally and for all 770 years

| Key | Mod line | Vanilla value → effect |
|---|---|---|
| `rank_empire_theocracy` | 171 | `"$rank_empire$"` → **"Caliphate" for every theocratic empire, forever** |
| `rank_empire_theocracy_prefix` | 173 | `"Holy"` → blanked globally |
| `rank_empire_theocracy_ruler_male` | 172 | `"Priest-Emperor"` → "Caliph" globally |
| `HRE_LEADER_MALE` / `.long` / `.short` | 236-238 | `"Holy Roman Emperor"` / `"Emp."` → **"King of the Romans" / "King" permanently** (historically Emperor from 1155) |
| `HRE_LEADER_FEMALE` / `.long` / `.short` | 239-241 | same |
| `CAT`, `CAT_ADJ` | 138-139 | "Catalonia"/"Catalonian" → "Barcelona"/"Barcelonese" |
| `barcelona_dynasty` | 140 | "Aragon" → "Barcelona" |

All look intentional for 1066. None is annotated as an intentional global
override, and none is period-gated. The sibling repo carries the identical
class as a standing open decision for `rank_empire_horde`.

**Suggested resolution:** an explicit allow-list in the harness, the way
`_INTENTIONAL_COA_OVERRIDES` already works for arms, plus one comment per key
saying it is deliberate.

### N2. `government_reform_slots = 1` on all five reforms rests on an inference

`zz_1066_reforms.txt:3-12` justifies it as *"so it does not consume one of the
country's reform slots"*. **That a setup-assigned reform consumes a slot at all
is stated nowhere.** Vanilla's own uses (`monarchy.txt:169`,
`country_specific.txt:22/85/291/…`) all read as deliberate *bonuses*. If
setup-assigned reforms do not consume slots, SEL gets **+2** free reform slots
and FRA / PAP / FAT **+1** each.

This is precisely the "a wrong inference corrupts the whole block" class.

### N3. `cultures_capacity = 6` is double vanilla's ceiling

`zz_1066_reforms.txt:63`; vanilla's max is 3 (`country_specific.txt:3909`). The
file says so and calls it a play-sized calibration. Flagged only because it is
the one magnitude in the mod with no vanilla precedent.

### N4. Dropping `middle_kingdom` leaves 200 landed countries in no IO at all

`15_international_organizations.txt` keeps 35 of vanilla's 53. **All 10 dropped
IO types have a creation date after 1066** — `guelphs_io`/`ghibellines_io` 1125,
`tribal_confederation` 1142, `lordship_of_ireland` 1177, `japanese_shogunate`
1192, `tatar_yoke` 1240, `ilkhanate` 1260, `middle_kingdom` 1271,
`jurchen_confederation` 1300, `swiss_confederation` 1307 — so the drop is
principled. But `middle_kingdom` alone leaves 200 still-landed countries (CHI,
KOR, TIB…) outside any IO, `jurchen_confederation` 48 more, `tatar_yoke` 31,
the Italian factions 29. Correct for 1066; a large system currently absent
rather than replaced. The Song would need their own IO.

### N5. All 45 new tags ship `starting_technology_level = 3` at a 1066 start

That is vanilla's 1337 value. This mod's own `KNOWLEDGE.md:187-194` argues the
other way. See also Part 4's correction to what that field actually does — the
answer changes the size of the decision, not its existence.

### N6. 34 of 45 new tags fall through to the generated-arms path

Deliberate, documented, and guarded by `_GENERATOR_OK` in `verify_mod.py:924`
(which does a three-way check plus a stale-entry reverse check). Recorded only
because `zz_1066_flags.txt:9` says "the remaining 33" and the real number is 34.

## PART 4 — DOCUMENTATION: what is wrong, and what is missing

These matter more than the code findings, because they are read at the start of
every session and written *from*.

### 4.1 WRONG — `CLAUDE.md:184-189`, the "SKE law". The most dangerous sentence in the doc set.

> "**A tag that is DEFINED but holds no land is brought onto the map by
> `change_location_owner` alone.** No formable, no `create_country_from_location`.
> Vanilla revives SKE — landless at 1337, identity-only block in
> `setup/countries/_scandinavia.txt` — with a plain
> `location:asbo = { change_location_owner = c:SKE }`
> (`events/DHE/flavor_swe_dan.txt:4`). The `culture_definition` and
> `religion_definition` fields in a `setup/countries` block exist precisely so
> the engine can instantiate a tag that comes into existence later."

Every load-bearing clause is false:

1. **SKE is not landless and has no identity-only block.**
   `10_countries.txt:308-314` gives it eleven locations
   (`varberg halmstad kungsbacka ronneby bregne solvesborg gladsax osby
   helsingborg lund malmo`) plus revolter claims at `:316-318`.
   `flavor_swe_dan.txt:28-38` shows SKE is already alive *and already SWE's
   subject* when the event fires. The event moves two locations to an existing
   landed country. **The only cited attestation does not attest the law.**
2. **An identity block alone is registration, not a country.** 2337 of 2337
   real vanilla tags have BOTH an identity block and a `10_countries` block;
   the only three registry entries without one are `DUMMY`, `MER`, `PIR`.
3. **Those two fields are release-time fields** and are not read on a
   `change_location_owner` handover — measured twice in the Mongol Resurgence
   session (a crimean/sunni block arriving Orthodox, a tungusic_shamanism block
   arriving Tengri).

The sentence is cited by name as "the SKE law" at `SITUATION-SPECS.md:173` and
`NEW-COUNTRIES-DESIGN.md:52`, and `SITUATION-SPECS.md:581-583` plans to
instantiate the Pecheneg tag by exactly this route.

> **VERIFY:** open `10_countries.txt:308-318` and count SKE's locations. Then
> read `flavor_swe_dan.txt:28-38`. Then run the set difference between the
> identity blocks in `in_game/setup/countries/*.txt` and the country blocks in
> `10_countries.txt` — expect exactly `{DUMMY, MER, PIR}`.

### 4.2 WRONG — `NEW-COUNTRIES-DESIGN.md:48-54` contradicts `:113-121` in the same file

### 4.9 IMPRECISE — `verify-tags/SKILL.md:32-35`: the tag census
